# Faur v0.40.0 — 2026-11-16

## Features

- **Expose a project-local Pi agent through MCP.** Ask `/faur Create Jared in .agents/jared and expose audit and review as MCP tools.` The optional `mcpServer` declaration defines named public operations, descriptions, JSON input schemas and prompt bindings to the lead, with an explicit target project root and separate runtime tool/environment allowlists.
- **Self-contained stdio hosting.** Generated MCP projects include bundled Faur package assets, pinned Pi/MCP dependencies and a lockfile. Run `npm ci` in `.faur-mcp`, then register the entry point locally using the generated client-specific instructions. No Faur checkout or global Pi/Faur installation is required. This is an explicit, opt-in exception to the maker-only boundary; ordinary/minimal projects remain unchanged.
- **Fresh execution and lifecycle handling.** Every operation shares validation, fresh Pi SDK execution, timeout/cancellation, active-tool and same-process-group cleanup, and text-result mapping. One call runs per server at a time; overlap is rejected. Finish calls before maintenance, then restart/reconnect to expose updated operations.
- **Manage agents from the main project.** `/faur agents` lists direct `.agents/<name>` children identified by their existing `.pi/system.yaml`; bare `/faur` offers a picker. `/faur agent jared <request>` targets explicitly, and named requests such as `/faur Update Jared’s review operation` also work. New independent agents default to `.agents/<name>` unless another location is requested. No extra identifier or registry is introduced.
- **Reuse existing maintenance protections.** Parent-project maintenance keeps one scoped controller and the same preview/approval/apply path. Target switching cannot silently discard a pending proposal; `/reload` restores the selected agent and tool restrictions. Selection never loads the target's executable resources or treats caller tools/history as target execution evidence.

## Fixes and ownership

- Hash-protect bundled MCP resources and definitions against authored edits. Retire unchanged distribution assets through the existing checked apply path; keep installed dependencies ignored when removing the interface.
- Show executable distribution/dependency assets by path, hashes and direct pins in bounded package-style approval summaries, while retaining complete operational configuration diffs.
- Handle stdin EOF, symlinked MCP entry paths, invalid input, generic execution failure, timeout, cancellation and active shell-tool cleanup. Keep protocol stdout separate from worker diagnostics and redact exact declared environment values from final answers as defense in depth.
- Keep `/faur exit` session-scoped even when the selected target disappears; prevent preview cleanup through symlinked state directories.

## Verification and limitations

- The default suite, real-Pi parent-project RPC tests and opt-in MCP integration gate passed on the release tree. The MCP gate installs into an independent temporary project with spaces in its path and uses real local Pi/MCP with a deterministic local model endpoint, not a paid provider. It exercises two public operations, restart updates, failures, cancellation, process cleanup, scoped maintenance and local `/faur` discovery. The MCP dependency audit reported zero vulnerabilities.
- MCP hosting initially requires POSIX and uses Pi's built-in model catalog, not global logins or custom provider extensions. It does not load runtime specialists, skills or upstream MCP integrations. Declared environment variables must be supplied by the caller; credentials must not be committed.
- Configuration isolation and tool selection are enforced, **not OS/filesystem isolation**. Tools retain the OS account's access; prompts are advisory. Detached/background work outside the supervised process groups is not a supported daemon lifecycle. Output redaction is not general exfiltration prevention, and run success is not task success.
- Real-provider quality, human TUI editing, individual third-party client registration and other opt-in provider/systemd/delegation/clean-machine gates were not verified for this release. Generated projects do not update automatically.

## Install or update

```sh
pi install git:github.com/mihaiiova/faur@v0.40.0
```

Restart Pi or run `/reload`. Installations pinned to older tags do not move to this release automatically. Review and approve `/faur sync` to regenerate an existing project; for MCP projects, rerun `npm ci` if dependencies changed and restart/reconnect the server.
