# Faur v0.41.0 — Pi subscription authentication for MCP

Released 2026-11-16.

## Features

- Generated MCP hosts can explicitly reuse an existing Pi Codex subscription
  login with `mcpServer.auth.mode: pi-subscription`, provider `openai-codex`, and
  a host-only `authFileEnv` pointing to a private existing Pi auth.json.
- The trusted host uses Pi 1.5.2's public runtime APIs and native credential store,
  including cross-process locking, refresh and persistence. Only selected Codex
  request auth reaches each isolated worker over private IPC. No credential file
  is copied, no global Pi resources are inherited, and there is no interactive
  login or silent model/provider/API-billing fallback.
- Exact pinned-catalog compatibility is checked before credential access. Missing
  or unusable login, source permissions and refresh failures return sanitized,
  actionable errors. Explicit `--check-auth` inspects local metadata without
  refreshing; `--check-auth --resolve` permits OAuth refresh but no model call.
- Capability checks distinguish configuration, historical local auth resolution
  and historical successful model invocation. Ignored evidence contains only
  fingerprints/timestamps, not credentials, prompts or outputs. Generation,
  maintenance previews, registration instructions and strict schema validation
  cover the new option together.

## Boundaries and compatibility

- Isolated API-key mode remains the default; minimal-agent output and dependency
  pins are unchanged. No additional runtime tools or upstream MCP capabilities
  are granted.
- The native store internally parses the shared auth file, including unrelated
  entries; these credentials are not forwarded to workers. This is the explicitly
  approved host trust boundary, not a provider-filtered broker-process store.
- Invocation cancellation/timeouts still terminate workers independently. A
  started refresh remains owned by the host, which drains native writes on
  graceful shutdown. Clients must allow at least 20 seconds of stop grace; do not
  enable shared-login mode where that grace cannot be honored. Forced termination,
  storage failure and ambiguous remote rotation outcomes retain ordinary Pi's
  limitations; loss-free/crash-durable rotation is not guaranteed.
- Configuration isolation is not OS/filesystem isolation. Allowed same-user tools
  remain trusted. Local auth resolution is not provider acceptance or task success.
