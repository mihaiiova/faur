# Faur v0.42.0 — Full native-agent MCP execution

Released 2026-11-19.

## Features

- The optional external MCP server now runs the configured native Pi agent,
  rather than a reduced lead-only profile. Source instructions, skills, prompt
  templates, authored extensions, specialists, declared commands and upstream
  MCP use published Pi/package loading and inheritance policies.
- Every call starts a fresh native session in the agent source folder. The
  configured target is resolved to an absolute path and delivered alongside
  validated operation arguments as task context after skill/template expansion,
  including templates that omit `$@`.
- Generated hosts install from the normal locked registry dependencies. There
  are no modified Pi packages, local native tarballs, unpublished API
  prerequisites or separately required global Pi/Faur installations.
- Explicit toolchain PATH grants keep packaged Pi available to delegation;
  PATH is non-secret and is not redacted from legitimate answer text.

## Breaking changes and trust

- `mcpServer.tools` is removed and rejected as an unknown key. Configure native
  lead/specialist tools in the ordinary agent definition; the external MCP
  interface no longer supplies a second, narrower tool profile.
- Runtime cwd is the agent source, **not the target project**. Target file work
  must use absolute paths, and shell commands must explicitly change directory.
  These instructions are advisory, not automatic path rebasing or filesystem
  isolation. Registration cwd does not select the execution target.
- Explicit Pi Codex subscription mode now gives trusted native lead, specialists
  and tools direct access to the selected private native credential store,
  including other entries. The old lead-only broker boundary is removed. The
  store is symlinked, not copied; Pi owns locking and refresh. No automatic login,
  global credential discovery or API-billing fallback is introduced. Forced
  termination can interrupt refresh/persistence and require re-login.
- Ordinary native ancestor context/skill discovery and child resource policies
  apply. The target project's configuration is not the runtime cwd configuration.
  Fresh conversations do not isolate persistent source-local memory/files;
  keep project-specific state under the explicit target.

## Fixes

- Specialist instructions are generated as native Markdown bodies instead of
  YAML `systemPrompt`, which native pi-subagents did not use as file prompt text.
  Maintenance adoption/reconciliation and ownership tests use the same native
  representation. Minimal single-agent golden output is unchanged.
- Known package/resource/model failures return sanitized errors; calls never
  install missing code. Model output-length stops are errors, not successful
  truncated answers. Explicit authentication metadata checks include source
  `models.json` without refreshing credentials or making a model request.
- The bundled developer-maintenance extension opts out of MCP execution while
  remaining available for ordinary project maintenance.

## Upgrade and limits

Regenerate/reconcile older MCP projects with explicit preview/approval, remove
`mcpServer.tools`, review the expanded native execution/credential boundary,
install declared source packages explicitly, and restart/reconnect the server.
Preserve authored instructions; Faur does not silently overwrite edited files.
Older specialist prompt files need explicit regeneration/reconciliation to the
native Markdown-body format.

Native Pi can skip a nonexistent configured resource path without diagnostics;
reported discovery errors fail, but this adapter is not a second validator.
MCP startup is native behavior, not an all-server readiness guarantee. Calls are
single-flight per host; separate hosts are not coordinated. Bounded cancellation
and same-group cleanup do not guarantee termination of detached/background
specialists or escaped daemons. No OS sandbox or independent task-success
verification is claimed.
