# Faur v0.41.1 — Authored README reconciliation

Released 2026-11-17.

## Fixes

- `/faur` can reconcile an edited README in the same proposal as an MCP or
  other configuration change. Inspection includes its absolute path and
  redacted content; the planner can propose only additional documentation with
  `readmeAppend`, or preserve without additions with an empty string.
- Existing prose is preserved. The combined README/configuration diff requires
  explicit user approval; discard applies nothing, and changing README after
  preview invalidates apply. Exact already-present additions are not duplicated.
- Approval removes the obsolete scaffold header, making README fully authored;
  future generation leaves it unchanged instead of proposing generic text.
- Authored conflicts show absolute paths and supported resolution options.
  README conflicts no longer recommend unsupported drift adoption or deleting
  the file. Other authored conflicts still block the whole proposal.

## Boundaries

- Reconciliation is append-only, not a general or semantic merge. Contradictory
  prose is not rewritten automatically. No schema field, dependency, generated
  runtime hook or minimal-agent golden output changes.
- Apply retains existing stale-file checks, atomic per-file replacements and
  best-effort rollback on synchronous failures. It is not a crash-safe multi-file
  transaction or isolation from concurrent readers.
- No changes to Ex Libris, Mobbin authentication or live Mobbin requests were
  made. Tests use disposable generated projects and declared URLs only.

## Verification

- `bash test/test.sh` — passed; optional live-provider and integration gates

- Regression coverage includes custom README preservation alongside MCP
